# Knowledge Router

Use this compact router before loading background knowledge. It preserves the repository knowledge-base routing decisions without requiring files outside this skill.

## Routing protocol

1. Classify supplied and discovered evidence with [evidence-protocol.md](evidence-protocol.md).
2. Identify the decision or funnel stage under investigation.
3. Select one primary knowledge lens from the table below.
4. Add source detail only when attribution, limitations, or framework mechanics matter.
5. Add current evidence under [live-sources.md](live-sources.md) whenever freshness matters.
6. Select the smallest specialist set with [routing-map.md](routing-map.md).
7. Keep evidence, principle, hypothesis, and original execution separate.

Never load every lens for one investigation. A lens is a research direction, not evidence for a claim.

## Evidence-level router

- Classic direct-response and practitioner funnel, launch, offer, or lead frameworks are practitioner evidence. Attribute them and do not label them research-backed without independent support.
- Persuasion or behavior claims that materially affect a recommendation should use current primary research when available.
- CRO methods can structure investigation, but observed user evidence and owned measurement decide whether a diagnosis applies.
- Current ads, platform behavior, benchmarks, payments, policies, regulations, and market conditions require live evidence captured during the investigation.

If the fuller repository knowledge base is not installed, use these lenses to frame questions and research. Do not invent the missing source content or imply that it was consulted.
